# EmberPad

Base code for a personal offline iPad teaching app. The Ember House colour tokens, reusable type styles, original app and Companion artwork, and branded launch background are in place, along with the initial worksheet chrome and the toolbar strip; the teacher's on-device decisions are still pending. This is a development scaffold, not yet a classroom-ready release.

## Layout

| Path | Responsibility |
| --- | --- |
| `EmberPad.xcodeproj` | iPad app, macOS Companion, iOS unit-test bundle and inert `resign` aggregate target; local package dependency |
| `Apps/EmberPad` | SwiftUI library with UIKit PDFKit/PencilKit page overlays, model-owned ink, student-display scene, the pairing-code scanner and the Mac sync client |
| `Apps/Companion` | macOS menu-bar window: Drive EMBER source folder, document counts per subject with a not-read list, iPad pairing code, phase-2 placeholders, with no networking |
| `Apps/EmberPadTests` | iOS unit tests of app-layer logic, hosted by the EmberPad app |
| `EmberSyncKit` | Swift package target: validated manifests, streaming SHA-256, update planning, disk storage, expiry parser, the macOS Drive EMBER library reader, the transport-agnostic sync wire protocol, pairing credentials with their Keychain store and TLS-PSK connection parameters, the iPad's Bonjour connector and sync download, and tests |
| `Config/Shared.xcconfig` | Final `EMBERPAD_BUNDLE_ID` `io.github.ka1oww.emberpad` for the iPad app; the Companion target appends `.companion` so it never shares the iPad's App ID |
| `resign` | Uninstalled renewal script with its optional Outbox delivery, format helpers, disabled example config and LaunchAgent template |

No third-party app dependencies, extensions, entitlement files or capability-backed services. iPad deployment floor is 17.5, macOS floor is 14.0. The local build is Xcode 26.6 (17F113), iOS/macOS SDK 26.5. CI selects Xcode 26.6 on `macos-26`.

## Build and test without signing

```sh
swift test --package-path EmberSyncKit
xcodebuild -project EmberPad.xcodeproj -scheme EmberPad \
  -configuration Debug -destination 'generic/platform=iOS Simulator' \
  -derivedDataPath /tmp/emberpad-ios CODE_SIGNING_ALLOWED=NO build
UDID=$(xcrun simctl list devices available --json | python3 -c 'import json,sys; d=json.load(sys.stdin)["devices"]; c=[x for v in d.values() for x in v]; print(next((x for x in c if x["name"].startswith("iPad")), c[0])["udid"])')
xcodebuild -project EmberPad.xcodeproj -scheme EmberPad \
  -configuration Debug -destination "id=$UDID" \
  -derivedDataPath /tmp/emberpad-test CODE_SIGNING_ALLOWED=NO ONLY_ACTIVE_ARCH=YES test
xcodebuild -project EmberPad.xcodeproj -scheme 'EmberPad Companion' \
  -configuration Debug -destination 'generic/platform=macOS' \
  -derivedDataPath /tmp/emberpad-mac CODE_SIGNING_ALLOWED=NO build
zsh -n resign/renew.zsh
plutil -lint resign/dev.emberpad.renew.plist
```

These commands do not install on a device, provision an App ID or need an Apple account. The bundle IDs are final: changing the iPad ID later means deleting the app and its ink. The checked-in `EmberPad.xcodeproj` and shared schemes are the source of truth. `Apps/EmberPad`, `Apps/Companion` and `Apps/EmberPadTests` are file-system synchronized folders, so adding or removing a `.swift` file there needs no `project.pbxproj` edit (`Info.plist` files stay referenced by path and are excluded from membership). Commit test changes with source changes.

The GitHub workflow runs package tests, both unsigned builds, the EmberPadTests simulator suite, and syntax/plist checks. Ink feel, touch routing, Pencil double-tap, rendering at 1x/2x, capture traits, external-display behavior and signing cannot be established by those checks.

## Offline library

Import PDFs with **Import from Files**, choosing an existing or new class name. Files open through security-scoped coordinated reads and are copied into the app. Encrypted/locked or unreadable PDFs are rejected. A Finder/Files delivery can also place PDFs at `Documents/Inbox/<Class>/<file>.pdf`; a loose Inbox PDF goes to `Unfiled`. The reserved `Documents/Inbox/EmberLibrary` folder is the Mac's library delivery, described below, and is never read as loose PDFs. Nested paths within a class are preserved as source identity. Inbox is checked on foreground and by **File Inbox**. Retained Inbox files are idempotent receipts, and are never deleted while a sender could be writing them. Symlink deliveries are skipped. No absent-file deletion is inferred from an incremental Inbox.

If separate import locations would otherwise share a class/path, EmberPad gives the later assignment an available visible filename suffix, preserving any existing suffixes. It remembers each source's assignment, so re-imports keep their identity across picker batch order, Inbox/Files arrival order and app/store reopen. A changed file at that same source path follows the version rules below.

Each document version has its own `Application Support/Library/<UUID>/` folder:

```text
original.pdf            # untouched PDF bytes for this version
doc.json                # format 2: source class/path/hash and publication record, dates, status, ink pages, paired copy
page-0.drawing          # zero-based PDF page, native PKDrawing.dataRepresentation()
page-1.drawing
```

The app's `DocumentSession` owns every page drawing and updates from `canvasViewDrawingDidChange`, independently of overlays. It saves about one second after changes and flushes on editor exit and backgrounding. Save errors stay visible; corrupt saved ink never silently becomes an empty drawing. Storage uses Documents/Application Support, with no reliance on Caches. Deleting the app still deletes this data; backup is a later phase.

Same path and checksum is a replay. New bytes without ink replace the current copy while retaining the prior folder in hidden `.Previous` for 30 days. New bytes with ink create an **Updated** copy and mark the annotated one **Older version**; ink never moves to new bytes. An open, uninked worksheet is pinned: changed deliveries wait until the editor closes so an old canvas cannot write onto a replacement PDF. Recheck Inbox after closing it. Previous-version pruning is an explicit store operation; the base keeps versions conservatively until that maintenance path is wired.

The complete-manifest planner also returns archive and no-download relink actions for Mac deletion/rename. Ambiguous identical hashes are imported and archived conservatively rather than assigning somebody else's ink. Full manifests arrive by the Inbox copy or by sync, described below; the iPad has no cloud folder access.

### Library model v2

A version-2 manifest gives every entry a publication record: subject, optional class tag, a stable paper key, role (`student` or `teacher`), display title and an optional `archived` mark (written only when true). Each paper key has at most one copy per role. An archived copy is listed only under **Archived** on the iPad, beside copies archived because they left the Mac library, and it still pairs with its counterpart. Version-1 manifests and Inbox deliveries still load as Student copies whose subject is the class folder; the iPad never infers a Teacher role from a file or folder name. Format-1 `doc.json` files still load as Student copies and are upgraded to format 2 when next written. Format 2 keeps the publication record in `source` and stores `pairedDocumentID`: the single current copy of the opposite role with the same paper key, recomputed after document imports, replacements, relinks and archives.

A document's identity is its path plus role, and its role never changes, so one path may hold a Student and a Teacher copy and a role change files a new copy beside the archived old one. Student copies keep the rules above. Teacher copies cannot be inked in this version: the store refuses Teacher ink, a changed Teacher copy replaces in place, and a Teacher copy at a new path follows its paper key to its existing document. No rule replaces an inked document, moves ink onto other bytes or relinks across roles.

### Library source: Drive EMBER folder (macOS)

`EmberLibrarySource` builds a version-2 manifest from the Google Drive EMBER folder. `EmberLibrarySource.discoverDriveRoot()` finds it at `~/Library/CloudStorage/GoogleDrive-*/My Drive/EMBER`, taking the first Drive account folder by name that has one; a root passed in explicitly is used as given, and tests use synthetic trees. It only reads, and it never follows symlinks.

- **What is included:** eligible regular `*.pdf` files below the root, case-insensitively, including single-copy notes, commonly asked question booklets, answering techniques and TYS papers. Discovery is based on files; sign-off and publication records are not consulted. Hidden entries (names starting with `.`) and symlinks are skipped. Non-PDF files are skipped and counted. Build output is skipped and counted, never read: PDFs below folders named `redraws`, `crops`, `_build`, `artifacts`, `_assets`, `_qa` or starting with `_redraws` (case-insensitive), and the shared logo `ember-star.pdf`.
- **Subject:** the top-level folder: `EMBER CHEMISTRY` is Chemistry, `EMBER MATH` is Math, `EMBER PHYSICS` is Physics and `EMBER BOOKLETS (MI + JC)` is Booklets. Any other top-level folder is a subject under its own name, except that leading underscores are removed from an underscore folder's subject name; a PDF directly in the root is General. The path below the subject folder is the manifest path and the title context: `NOTES & TUTORIALS/Topic/Notes.pdf` shows as **NOTES & TUTORIALS / Topic / Notes**.
- **Teacher pairing by name, in one directory:** a name ending in a Teacher marker pairs with the same-directory PDF whose name is identical once its marker is removed (case and repeated spaces ignored). Markers include `Teacher`, `Teacher Copy`, `Teacher Version`, `Solutions`, `Answers`, `Answer Key` and `Mark Scheme`, either in brackets (`(Teacher)`), after a hyphen, dash, underscore or em dash, as a trailing word, or as the whole name (`teacher.pdf`). A bracketed group at the end that contains the word Teacher also counts. A Student marker (`Student`, `Student Copy`, and corresponding version forms) is removed the same way. Both copies share the paper key `<subject>/<folders>/<name without marker>`. A PDF with no partner is a single-copy Student document, and an unpartnered Teacher-marked PDF is still delivered with role `teacher`, so it never becomes a Student copy.
- **Archive folders:** a delivered document below a non-build-output folder whose name starts with `_` (such as `_legacy-archive`) is delivered with the `archived` mark. A nested underscore folder stays in its source path but not its title; for a top-level underscore folder, leading underscores are removed from the subject name. Build-output folders remain excluded even when their names start with `_`.
- **Identity and misses:** content identity is the SHA-256 of the bytes. A file or folder that cannot be read (Drive offline, not downloaded yet, or metadata unavailable) is a miss with reason `unreadable`, never a deletion. Other miss reasons: `duplicate-paper-key` (two copies of one role under one key, or one path; all are held back rather than guessed between), `privacy-withheld`, `identical-copies` and `student-matches-a-teacher-copy` (a Student copy whose bytes equal any Teacher copy is held back, and the Teacher copy is still delivered), and `invalid-name`.
- **Carry-forward:** pass the previously delivered manifest as `previous`. Each previous copy (paper key and role) that is not delivered this run is carried forward unchanged, as `source-vanished`, `source-unreadable` or `held-back`, so a vanished source means "no update" and the planner never archives it. A carried copy still passes the privacy and cross-role checks.

Class is the folder- or file-name prefix (`MI PU1-3`, `YIJC JC1-2`, `NYJC-EJC JC1-2`, `SEC 1-4`), the first folder below the subject that has one winning over the file name. A prefix can also come from the alias table loaded from `~/Library/Application Support/EmberPad/class-aliases.json` and passed to `EmberLibrarySource` (synthetic example: `EmberSyncKit/Examples/class-aliases.example.json`). With no prefix, the copy belongs to **All classes**. Alias values must be known class codes or short uppercase tags matching `^[A-Z0-9][A-Z0-9-]{0,11}( [A-Z0-9][A-Z0-9-]{0,11}){0,2}$`; other values are skipped and counted. In every folder and file name, each `Sec 1-4` or `S1-4` token is checked against the complete word segment before it (after the preceding section token, if any): it must be empty, a class code or an alias key. Otherwise that segment's words are withheld and removed, and no class comes from it. Non-class name words in alias keys and configured `withhold` terms are also withheld. The real table is personal data and never goes in the repository. A final check rejects any copy whose emitted class tag is invalid, or whose source path, title, subject or paper key still contains a personal-name shape or withheld term. The local path of each copy and the miss list stay on the Mac and never go in the manifest.

The macOS Companion defaults to the discovered Drive EMBER folder and remembers a folder chosen with **Choose EMBER folder…**. Click **Prepare iPad library** to read it on demand; opening the window or changing folders does not start a scan. The window shows document counts per subject, the pair, single-copy and archived totals, and the PDFs or folders not read this time with their reasons. Preparation never writes inside the EMBER folder; it writes the iPad Outbox described below. See the [light](docs/screenshots/companion-light.png) and [dark](docs/screenshots/companion-dark.png) screenshots.

### Library delivery: Outbox to Inbox

**Prepare iPad library** writes the Outbox at `~/Library/Application Support/EmberPad/Outbox`: `EmberLibrary/manifest.json` (the version-2 manifest) and `EmberLibrary/files/<sha256>.pdf`, one PDF per content hash, so no local file name leaves the Mac. The Outbox's own manifest is the `previous` manifest for the next read, so a copy missing from Drive is carried forward with its bytes from the old Outbox. Every PDF read this run is copied in and checked against its manifest hash; if one changed meanwhile, the write fails and the old Outbox stays. A new Outbox is built in a hidden staging folder beside it and swapped in with one atomic rename (`RENAME_SWAP`), so a reader sees either the whole old Outbox or the whole new one.

The optional delivery in `resign/renew.zsh` copies the Outbox into the iPad's `Documents/Inbox` (see [resign/README.md](resign/README.md)). On foreground and **File Inbox**, the iPad reads `Inbox/EmberLibrary/manifest.json`; a manifest that is cut short or not version 2 changes nothing. It plans the whole manifest through `DiffPlanner`, then runs each action that needs bytes only when that PDF is present with the manifest's size and SHA-256 and opens as a PDF. Archive actions run only when every such action succeeded, so a half-delivered or interrupted copy files what arrived and archives nothing; the next check finishes it. Ink rules are the store's usual ones: an inked copy gets an **Updated** version beside it, and an open worksheet waits. Only documents that came from a library delivery are ever archived; worksheets imported from Files or loose Inbox PDFs are not. A completely applied delivery is recorded by its manifest hash and not applied again, and only then are Inbox copies the manifest no longer lists removed. Loose Inbox scanning skips the reserved `EmberLibrary` folder.

### Sync wire protocol

`Wire*.swift` in EmberSyncKit is the private protocol a later transport carries between the Mac (server) and the iPad (client). It opens no connection itself: `WireClientSession` and `WireServerSession` are pure state machines that take received bytes and the current time and return frames to send and events, so a driver moves bytes and calls `tick` on a timer. The server emits at most one frame per `receive` call; send that frame, then call `receive(Data(), now:)` while `hasPendingInput` is true before reading more transport bytes. This bounds response generation for coalesced requests while preserving the transport's backpressure. `InMemoryWireTransport` is an in-process pair with bounded buffers for tests; it opens no socket.

A frame is a 1-byte type, a 4-byte big-endian payload length and the payload. The client sends HELLO (magic `EMBR`, version range, role, largest chunk and manifest it accepts) and the server answers HELLO with the highest common version. The client then sends GET-MANIFEST (answered by MANIFEST, the `ManifestCodec` JSON) and GET by SHA-256 with initial credit (answered by DATA chunks at explicit offsets and a final END with the total length). Each request has a strictly increasing client-chosen id and gets exactly one terminal frame: MANIFEST, END or a request ERROR (not found, cancelled, stalled, busy, manifest too large, unavailable).

Flow control is per transfer credit: the server sends only bytes the client has granted, chunked to the smaller of both peers' limits and round-robin across transfers. The client grants WINDOW increments only as the app reports bytes written, so a slow writer holds at most one window. The client checks every chunk's offset and credit, hashes the bytes as they arrive and reports a completed file only when the size and SHA-256 both match. CANCEL fails a request at once and discards its late bytes until the server acknowledges. A transfer with credit outstanding and no progress stalls on the client; one the client leaves without credit is dropped by the server. Unknown, out-of-direction and oversized frames are rejected from their headers before their payloads are buffered; malformed payloads are rejected when decoded. These violations close the session with a protocol-violation ERROR. Every length is bounded: chunks to 1 MiB, manifests to 32 MiB and credit to 16 MiB per transfer; concurrent requests are limited by `WireLimits`.

### Pairing

`PairingCredential`, `PairingKeychain` and `PairingTLS` in EmberSyncKit pair one Mac with one iPad. In the Companion's iPad section, **Pair iPad…** creates a pairing if there is none: a 256-bit secret and a 128-bit service id from `SecRandomCopyBytes`. The Mac saves it in its Keychain and shows it as a QR code (`EMBERPAD-PAIR:1:<service id>:<base64url secret>`, not a URL). The code opens in its own window with `sharingType = .none`, which keeps it out of screenshots and screen sharing where macOS honours that setting. The window closes after five minutes or on **Done**. On the iPad, touch and hold **File Inbox** and choose **Pair with Mac…**, then scan the code with the camera. That needs only `NSCameraUsageDescription`, no entitlement. The camera preview is replaced while the screen is captured or a student display is connected. The scanner refuses any code not in the exact current format, and a refused code changes nothing.

Each side keeps the pairing only as one generic-password Keychain item (this-device-only on iPad, never synchronised). It is never stored in UserDefaults or files. Descriptions and reflection print `<redacted>` in place of the secret, and the app UI shows only the service id's first six characters and the date. **Forget iPad** on the Mac and **Forget Mac…** on the iPad each delete their own item. Once the Mac forgets, the old secret is useless: any new pairing has a fresh secret and service id. Pairing again overwrites the item, and **Pair iPad…** on the Mac treats an unreadable (corrupt) item as absent and replaces it with a fresh pairing.

`PairingTLS.parameters(for:)` is the only source of connection parameters for sync, and the Mac listener and iPad client use the same parameters. They set up TCP inside TLS 1.2 with a single PSK cipher suite (`TLS_PSK_WITH_AES_128_GCM_SHA256`) and peer-to-peer Wi-Fi on. The key is HKDF-SHA256 of the secret, bound to the service id; the PSK identity names the pairing, never the secret. The Bonjour type is `_embersync._tcp` and the instance name is the service id. Loopback tests over real sockets show the paired peer connects and negotiates that suite. A wrong key, a peer from another pairing, plain TCP, certificate TLS and a server with the wrong key all fail the handshake, and nothing they send reaches the server's reader. The Keychain store is tested against the real macOS Keychain under throwaway service names. The iPad app tests use an in-memory store, because the unsigned Simulator host has no Keychain entitlement. The iPad browses and connects as described below. The Companion's listener is EP-23 and is not built yet, so for now the Mac cannot tell whether the code was scanned.

### Sync client (iPad)

Once paired, EmberPad syncs on launch, on every return to the foreground and on **Sync now** (in the library's Mac sync row and in the **File Inbox** menu). `LibrarySyncConnector` browses Bonjour for `_embersync._tcp` with peer-to-peer Wi-Fi on, takes only the instance named by the pairing's service id, and connects with `PairingTLS.parameters(for:)`, so a Mac without the pairing's key never gets a byte. The app declares `NSLocalNetworkUsageDescription` and `NSBonjourServices`; no entitlement is needed. A Mac not seen within 8 seconds is reported as not found, with nothing changed. Networking is foreground-only: leaving the app cancels the sync, and nothing runs while the iPad is not paired.

`LibrarySyncDownloader` sends HELLO, asks for the manifest, plans it against the library with `DiffPlanner` and requests by SHA-256 only the PDFs an import, replace or new-version action needs. Each PDF is written to a hidden partial file and gets its `<sha256>.pdf` name only after the session has matched its size and SHA-256; bytes that do not match are dropped. The row shows progress by bytes and files. The manifest is written last, atomically, in the same `EmberLibrary/manifest.json` and `files/` layout as the Inbox delivery, in `Application Support/Sync` (outside the Files-visible Documents folder). PDFs already verified stay for the next sync, which fetches only the rest.

The download is then filed by `LibraryDeliveryApplier.applyNewest`, the one manifest path for both routes: of the Inbox copy and the sync download it applies the one with the newer `generatedAt` (sync on a tie) and never the older one in the same check. The applied-delivery receipt now records the manifest's `generatedAt`, so an older manifest arriving later by either route is skipped as superseded instead of archiving papers the newer one added. All the Inbox rules above hold: ink is saved first, an inked copy gets an **Updated** version beside it, an open worksheet waits, and a cut-short sync files what arrived and archives nothing. After a complete apply the downloaded PDFs are removed, since the library holds them. **Last synced** is recorded only when the whole download arrived and the library holds a manifest at least that new.

The EmberSyncKit tests run EP-16's ink-safety tests over both routes, and run the client against a minimal in-test server built on `WireServerSession`, in memory and over real TLS-PSK loopback sockets. Bonjour browsing against an advertised in-test server runs only with `EMBERPAD_BONJOUR_TESTS=1`, because it uses the local network. The iPad tests drive `SyncClient` through `LibraryController` with synthetic PDFs. The end-to-end test against the Companion server (EP-23) is added once that server exists.

## Page and presentation seams

`WorksheetPageRenderer`/`PageRendererFactory` isolate option A (`PDFView` with a `PKCanvasView` overlay per page) from a later option B. `DocumentSession` and the storage layout survive that replacement. The worksheet scrolls continuously (vertical, 16 pt page gaps with shadows on the canvas token); every ink canvas is forced to the light style so black ink never inverts in dark mode.

Theme tokens are defined in `Apps/EmberPad/Theme.swift`; the app chrome uses light/dark color sets in `Apps/EmberPad/Assets.xcassets`, while ink colors stay fixed for the white worksheet page. The fountain-pen default is black at the middle width (2.5), and the marker default is translucent yellow at 18. See the [light](docs/screenshots/theme-tokens-light.png) and [dark](docs/screenshots/theme-tokens-dark.png) token previews. The editor nav bar (serif title with page/save caption, share pill, Teacher-copy toggle, undo/redo, More menu), the capture-leak and ink-not-saved banners, and the page pill use those tokens; the floating Teacher card is a later package.

The original worksheet-and-pen AppIcon and `bg`-coloured iOS launch screen, plus the Companion's monochrome menu-bar glyph and window badge, are documented with their vector sources and raster exporters in the [iPad](Apps/EmberPad/Brand.Sources/README.md) and [Companion](Apps/Companion/Brand.Sources/README.md) source notes. See the [home-screen icon screenshot](docs/screenshots/home-screen-icon.png).

Tools come from the toolbar strip under the nav bar (`ToolbarStrip.swift`), the same on 17.5 and 18; there is no `PKToolPicker` and no Tools menu. Left to right: lasso | fountain pen, highlighter, eraser | greyed shapes, text, image and laser pointer (a tap shows a "coming later" toast) | the active tool's controls. Pen and highlighter each have three colour presets (up to 12 through the system colour picker) and three widths; the eraser switches Partial or Whole stroke, with three sizes for partial. Tapping the selected tool again opens its settings popover: colour reorder and removal, and the pen-gesture and straight-line switches, which are stored but stay disabled until their packages ship. `ToolState` persists the current and previous tool, presets, widths, eraser mode and size and those switches in `UserDefaults` (`toolState.v1`, colours as hex), and sets the PencilKit tool on every page canvas. Apple Pencil double-tap and Pencil Pro squeeze follow the iPad's own setting: switch to eraser, switch to previous, or open the current tool's settings; ignore and system shortcut do nothing. Every switch shows a toast below the strip for 1.3 s. Worksheet drawing is Pencil-only; fingers pan/zoom. Undo/redo buttons and multi-finger double-taps route to the active canvas. Validate the eraser modes, double-tap and touch/undo behavior on the actual iPad before relying on them. See the strip with the [pen](docs/screenshots/toolbar-strip-pen-light.png) ([dark](docs/screenshots/toolbar-strip-pen-dark.png)), [highlighter](docs/screenshots/toolbar-strip-highlighter-light.png), [eraser](docs/screenshots/toolbar-strip-eraser-light.png) and [lasso](docs/screenshots/toolbar-strip-lasso-light.png) selected, the pen settings popover ([light](docs/screenshots/tool-settings-pen-light.png), [dark](docs/screenshots/tool-settings-pen-dark.png)) and the [Pencil toast](docs/screenshots/tool-toast-light.png).

The external scene uses `UIWindowSceneSessionRoleExternalDisplayNonInteractive`. Its model accepts only a worksheet page and committed drawing. It shows a neutral **Paused** view while the main scene is inactive. Editor chrome follows the viewport-centered page, while the student snapshot follows the focused canvas and its ink; the snapshot is rendered at full-page scale. In-progress strokes, follow-zoom and external-scene recording are future work.

Debug builds expose **Device checks** in the library's Debug section, with pass/fail results for the scene, log, PDF and Pencil checks. The probe appends scene and capture snapshots to `Documents/device-checks.log`, provides a runtime-generated synthetic writing-trial PDF, and can replace the external student scene with a solid-colour, role-labelled test pattern. Its scribble recorder accepts Pencil or touch input, labels each saved drawing `erase` or `keep`, and exports the collected stroke samples as versioned JSON through Files. Samples are held in recorder state and are not persisted unless exported; they are not added to the device-check log or uploaded. These controls are compiled out of Release builds.

The student view's page snapshot can only be built through `StudentSafeDocument`, whose failable initializer accepts only a Student-role record, from a session that supplies that record's own page and drawing. A Teacher copy opened as the main page therefore shows **Teacher copy · private** on the student view, never its pages. `sceneCaptureState` hides private content when the main scene is captured without an external scene, and whenever inactive: a Teacher copy's pages and the private-answer pane then leave the view hierarchy and draw no pixels, rather than being blurred or covered. Pairing is not used by the presentation layer yet, and no private-answer URL is assigned. AirPlay/HDMI, QuickTime, recording and capture-trait behavior must be checked with the teacher. Leaving the app can restore system mirroring; stay in EmberPad while sharing. There are no private UIKit capture-hiding tricks or iOS 27 APIs.

The library reads `embedded.mobileprovision` best-effort: amber at 48 hours or less, red below 24 hours, unknown when absent/malformed (normal for unsigned Simulator builds). This parses only a reminder, not a signature or security decision. The library shows the Inbox delivery time and, once paired, the last completed sync time; neither is shown until it has happened.
